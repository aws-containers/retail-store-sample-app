# S2-M03 - ECR module: repositories for the retail services

**Sprint:** S2 Terraform Foundation (VPC, EKS, ECR, data) (PDF Step 2 (3 h))  
**Owner:** A  
**Estimate:** 30 min  
**Depends on:** S2-M01  
**Teacher's requirement:** PDF section 3, Step 2 'ECR repositories (retail-ui, ...)'; section 4 File 1

## Why this issue exists
Jenkins will push the ui image here (S4). The PDF lists retail-ui and 'retailcart' (a typo); we create one repo per microservice with a consistent name so nothing has to be renamed later.

## Steps
1. Create repositories: retail-ui, retail-catalog, retail-cart, retail-orders, retail-checkout via a for_each over a list.
2. force_delete = true (so `terraform destroy` works even when images exist), image_tag_mutability MUTABLE, scan_on_push = true.
3. Outputs: map of repository URLs.

## Useful commands
```bash
aws ecr describe-repositories --query 'repositories[].repositoryName'
```

## Done when (acceptance checklist)
- [ ] 5 repositories exist after apply and are gone after destroy.
- [ ] URLs exposed as outputs.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- Because everything is destroyed every session, ECR images disappear too. The first pipeline run of each session re-creates the ui image. This is expected.

## Out of scope (do not do here)
- Pushing images (S4).

## Handoff
ECR URL for retail-ui is an output used by Jenkins.
