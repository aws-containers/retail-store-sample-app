# S2-M01 - Terraform skeleton: providers, versions, module layout

**Sprint:** S2 Terraform Foundation (VPC, EKS, ECR, data) (PDF Step 2 (3 h))  
**Owner:** A  
**Estimate:** 45 min  
**Depends on:** S1-M03  
**Teacher's requirement:** PDF section 3, Step 2; section 4 File 1

## Why this issue exists
Everything in S2 plugs into one consistent layout. The PDF's main.tf is a single file and references a subnet resource that it never defines, so we split it into modules and add the missing network part.

## Steps
1. Create terraform/envs/lab/{main.tf,variables.tf,outputs.tf,versions.tf} and empty module folders terraform/modules/{network,ecr,eks,data}.
2. versions.tf: required_version >= 1.10, aws provider ~> 5.x (or 6.x, pick one and pin it). provider region from variable (default us-east-1).
3. variables: cluster_name (default eks-shopops), kubernetes_version, az_names, tags. Default tags on the provider: Project=shopops.
4. data "aws_iam_role" "lab_role" { name = "LabRole" } lives in envs/lab and its ARN is passed into the eks module.
5. Run `terraform fmt -check` and `terraform validate` in CI later; do it locally now.

## Useful commands
```bash
cd terraform/envs/lab && terraform fmt -recursive && terraform init (with backend flags) && terraform validate
```

## Watch out
- Do NOT use `module "eks" { source = "terraform-aws-modules/eks/aws" }`: it creates IAM roles, and Learner Lab denies iam:CreateRole. Other Learner Lab EKS projects on GitHub use raw aws_eks_cluster / aws_eks_node_group for this reason.
