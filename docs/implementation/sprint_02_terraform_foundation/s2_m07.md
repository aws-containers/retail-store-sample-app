# S2-M07 - `make up`, `make down` and cleanup script with CLI verification

**Sprint:** S2 Terraform Foundation (VPC, EKS, ECR, data) (PDF Step 2 (3 h))  
**Owner:** A  
**Estimate:** 1 h  
**Depends on:** S2-M04, S2-M05, S2-M06  
**Teacher's requirement:** PDF section 4 File 3 (scripts/cleanup.sh); Deliverable 6

## Why this issue exists
A session lasts 4 h and cluster creation takes 10-15 min, so setup must be one command. Even more important: Kubernetes creates AWS resources that Terraform does not know about (load balancers from Service type=LoadBalancer, EBS volumes from PVCs). If they are left, `terraform destroy` can hang on the VPC and they keep billing.

## Steps
1. make up = terraform apply, update-kubeconfig, kubectl apply of k8s/storage (and later the app).
2. scripts/cleanup.sh (extends the PDF's 3-line version), in this order: delete Services in namespace retail -> `helm uninstall` releases in monitoring (ignore if absent) -> delete PVCs in monitoring -> wait until no load balancer remains -> terraform destroy -> verification.
3. Verification block (all must return empty): `aws eks list-clusters`, `aws elb describe-load-balancers`, `aws elbv2 describe-load-balancers`, `aws ec2 describe-volumes --filters Name=status,Values=available`, `aws ec2 describe-instances --filters Name=instance-state-name,Values=running`, `aws ec2 describe-nat-gateways`, ECR repos.
4. make down = cleanup.sh. The script must be safe to run when the cluster does not exist.

## Useful commands
```bash
make up
# ... work ...
make down
```

## Done when (acceptance checklist)
- [ ] Fresh account: `make up` ends with a ready cluster.
- [ ] `make down` ends with an empty verification report.
- [ ] Script tested twice, including re-run on an already-clean account.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- Never run `terraform destroy` directly before deleting the Services: the AWS load balancer holds network interfaces in your VPC and the destroy hangs.

## Out of scope (do not do here)
- Application content.
