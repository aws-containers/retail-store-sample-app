**Teacher's requirement:** PDF section 3, Step 2 'EKS cluster ... 2 t3.medium nodes (node_role_arn = LabRole)'; section 4 File 1

## Why this issue exists
This is the heart of the infrastructure. The PDF's file uses version 1.30; that version is now in EXTENDED support, which bills $0.60/h instead of $0.10/h for the control plane. We therefore use the newest standard-support version. We also need the instance metadata hop limit at 2 so that PODS can use the node's LabRole credentials (used by the cart to reach DynamoDB).

## Steps
1. Find the version: run the command below, take the newest version, put it in the variable kubernetes_version and in docs/conventions.md.
2. aws_eks_cluster: name var.cluster_name, role_arn = LabRole ARN, vpc_config { subnet_ids = both public subnets, endpoint_public_access = true }, access_config { authentication_mode = "API_AND_CONFIG_MAP" }.
3. aws_launch_template for the nodes with metadata_options { http_endpoint = "enabled", http_tokens = "required", http_put_response_hop_limit = 2 }.
4. aws_eks_node_group: node_role_arn = LabRole ARN, instance_types = ["t3.medium"], ami_type = "AL2023_x86_64_STANDARD", scaling desired 2 / min 1 / max 3, launch_template block, subnet_ids = both public subnets.
5. Outputs: cluster_name, endpoint, node_group_name and the node group's Auto Scaling group name (aws_eks_node_group.<x>.resources[0].autoscaling_groups[0].name) - S6 needs it for the CloudWatch alarm.
6. After apply: `aws eks update-kubeconfig --name eks-shopops --region us-east-1` then `kubectl get nodes`.

## Useful commands
```bash
aws eks describe-cluster-versions --query "clusterVersions[?status=='STANDARD_SUPPORT'].clusterVersion" --output text
terraform apply   # takes about 10-15 minutes
aws eks update-kubeconfig --name eks-shopops --region us-east-1
kubectl get nodes -o wide
```
