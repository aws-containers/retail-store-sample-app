## Why this issue exists
The cart service (S3) and the Lambda (S6) both need managed AWS data stores. The PDF's carts table has only a primary key `id`, but the cart service also queries by customer through a global secondary index. Upstream and the AWS EKS workshop both create it, so we add it or the cart will fail at runtime.

## Steps
1. Table shopops-carts: PAY_PER_REQUEST, hash_key id (S), attribute customerId (S), global_secondary_index name = idx_global_customerId, hash_key customerId, range_key id, projection_type ALL.
2. Table shopops-incidents: PAY_PER_REQUEST, hash_key id (S).
3. S3 bucket shopops-incidents-<account_id>, force_destroy = true, public access blocked.
4. Outputs: table names/ARNs and bucket name.

## Useful commands
```bash
aws dynamodb describe-table --table-name shopops-carts --query 'Table.{keys:KeySchema,gsi:GlobalSecondaryIndexes[].IndexName}'
```
