# S2-M02 - Network module: VPC 10.0.0.0/16, 2 public subnets, IGW, routes

**Sprint:** S2 Terraform Foundation (VPC, EKS, ECR, data) (PDF Step 2 (3 h))

**Depends on:** S2-M01  
**Teacher's requirement:** PDF section 2 (Network & Compute); Step 2 'VPC (2 public subnets, IGW)'

## Why this issue exists
EKS needs subnets in at least 2 AZs. We use public subnets only to avoid the NAT Gateway cost (about $35/month, as the PDF says). Nodes get public IPs so they can pull images and reach the control plane.

## Steps
1. VPC 10.0.0.0/16 with DNS hostnames + DNS support enabled.
2. 2 public subnets (10.0.1.0/24 and 10.0.2.0/24), map_public_ip_on_launch = true, in 2 AZs taken from a variable. Use us-east-1a and us-east-1b: us-east-1e does not support the EKS control plane, so never pick AZs blindly with `data.aws_availability_zones` index 0..1 without checking.
3. Internet gateway, one public route table with 0.0.0.0/0 -> IGW, associated with both subnets.
4. Subnet tags (required for Service type=LoadBalancer to find the subnets): `kubernetes.io/role/elb = 1` and `kubernetes.io/cluster/<cluster_name> = shared`.
5. Outputs: vpc_id, public_subnet_ids.

## Useful commands
```bash
terraform plan
terraform apply
aws ec2 describe-subnets --filters Name=vpc-id,Values=<vpc_id> --query 'Subnets[].[SubnetId,AvailabilityZone,Tags]'
```

## Watch out
- Without the two tags, `kubectl get svc ui` stays <pending> forever in S3 - this exact symptom is reported by other Learner Lab EKS projects.
