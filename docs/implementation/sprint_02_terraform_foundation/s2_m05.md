# S2-M05 - EKS add-ons (EBS CSI, metrics-server) + gp3 StorageClass

**Sprint:** S2 Terraform Foundation (VPC, EKS, ECR, data) (PDF Step 2 (3 h))  
**Owner:** A  
**Estimate:** 1 h  
**Depends on:** S2-M04  
**Teacher's requirement:** PDF section 3, Step 2 'aws-ebs-csi-driver add-on'; Step 5 'StorageClass gp3'; Step 7 HPA

## Why this issue exists
Prometheus/Grafana need persistent EBS volumes (S5) -> EBS CSI driver + a gp3 StorageClass. The HPA (S7) needs metrics-server, which EKS does NOT install by default and which the PDF forgot; we add it now as an EKS add-on.

## Steps
1. Terraform aws_eks_addon for aws-ebs-csi-driver and metrics-server, with depends_on = node group. Do not set a service_account_role_arn (we cannot create IRSA roles in Learner Lab); the driver will use the node role.
2. Create k8s/storage/storageclass-gp3.yaml: provisioner ebs.csi.aws.com, parameters type: gp3, volumeBindingMode: WaitForFirstConsumer, allowVolumeExpansion: true. Do NOT mark it default (EKS already has a default gp2 class); workloads will reference `gp3` explicitly.
3. Test: apply a PVC (1Gi, storageClassName gp3) + a pod that mounts it and writes a file; check the PVC becomes Bound and an EBS volume exists. Delete the test objects afterwards.
4. Check `kubectl top nodes` works (proves metrics-server).

## Useful commands
```bash
aws eks describe-addon --cluster-name eks-shopops --addon-name aws-ebs-csi-driver --query addon.status
kubectl get sc
kubectl get pvc,pv
kubectl top nodes
```
