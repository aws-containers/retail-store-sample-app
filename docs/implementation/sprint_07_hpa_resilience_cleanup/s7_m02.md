# S7-M02 - Load test and observe autoscaling

**Sprint:** S7 HPA, Resilience & FinOps Cleanup (PDF Step 7 (2 h))  
**Owner:** C  
**Estimate:** 1 h  
**Depends on:** S7-M01, S5-M02  
**Teacher's requirement:** PDF Step 7 'run a load test'

## Why this issue exists
Evidence that the HPA works, shown on a Grafana dashboard.

## Steps
1. Use k6 (docker run grafana/k6) or a similar tool from your machine against the ui LoadBalancer URL: ramp up virtual users for 5-10 minutes (scripts/loadtest.js).
2. In parallel: `kubectl get hpa -n retail -w` and the Grafana pod CPU/replica panels.
3. Capture: replicas going above 2, then scaling back after the test (scale-down is slow by default, about 5 minutes).
4. Note any errors/latency seen in the results for the post-mortem.

## Useful commands
```bash
docker run --rm -i grafana/k6 run - < scripts/loadtest.js
```

## Done when (acceptance checklist)
- [ ] Replica count above 2 observed and screenshotted.
- [ ] Test script and results committed in docs/evidence/.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- Keep the test short and stop it; extra nodes/load cost budget. Run it from your laptop, not inside the cluster.

## Out of scope (do not do here)
- Chaos tests.
