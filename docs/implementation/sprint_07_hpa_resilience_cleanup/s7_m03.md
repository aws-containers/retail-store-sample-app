# S7-M03 - Rolling update and rollback demonstration

**Sprint:** S7 HPA, Resilience & FinOps Cleanup (PDF Step 7 (2 h))  
**Owner:** B  
**Estimate:** 1 h  
**Depends on:** S4-M05, S3-M04  
**Teacher's requirement:** PDF Step 7 'validate a rolling update + rollback'; Deliverable 3

## Why this issue exists
Show that releases are safe and reversible.

## Steps
1. Good update: change something visible in src/ui, push, watch Jenkins deploy; during the rollout run `kubectl get pods -n retail -w` to show old/new pods overlapping and zero downtime (curl in a loop).
2. Bad update: deploy an image tag that does not exist or fails its readiness probe. Show that the old pods keep serving and the rollout stalls (`rollout status` fails).
3. Rollback: `kubectl rollout undo deployment/ui -n retail`, then `kubectl rollout history`. Time it.
4. Write the steps and timings in docs/rollback_demo.md.

## Useful commands
```bash
kubectl rollout history deployment/ui -n retail
kubectl rollout undo deployment/ui -n retail
```
