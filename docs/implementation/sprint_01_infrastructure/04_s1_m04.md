# S1-M04 - Build the EKS module

Sprint: S1 Infrastructure
Status: Planned - start after S1-M02 is complete
Owner: A

## Goal
After this mission `terraform apply` creates an EKS cluster with 2 t3.medium nodes using LabRole, and `kubectl get nodes` shows 2 Ready nodes.

## Dependencies
Do not start until:
```text
S1-M02 complete (network module outputs subnet_ids)
```
This mission MUST REUSE:
```text
terraform/modules/network outputs (do not create subnets here)
data.aws_iam_role.lab_role (do not create IAM roles - impossible in Learner Lab)
```

## Keep These Concepts Separate
| Concept | What it means | What it does NOT mean |
|---|---|---|
| Cluster role (role_arn) | Role the EKS control plane assumes | Role pods use |
| Node role (node_role_arn) | Role of the EC2 workers; pods reach AWS through it | A per-pod role (IRSA does not work in Learner Lab) |
| Hop limit 2 | Pods can reach instance metadata | Any extra permission |

## Rules That Are Already Decided
| Rule | Simple meaning |
|---|---|
| LabRole for cluster and nodes | No other role is created |
| Public subnets, no NAT | Cost control |
| Node group min 1 / desired 2 / max 3 | Max 3 leaves room for self-healing (S4-M05) |
| Addons: aws-ebs-csi-driver | Needed for gp3 PVCs |

## Implementation Plan
### Step 1 - cluster
Create: terraform/modules/eks/main.tf, variables.tf, outputs.tf
Invariants:
```text
cluster name comes from a variable defaulting to eks-shopops
endpoint_public_access = true
```
### Step 2 - node group with launch template
```text
instance_types = t3.medium
launch template sets metadata_options.http_put_response_hop_limit = 2
```
### Step 3 - addon and outputs
```text
aws_eks_addon aws-ebs-csi-driver
outputs: cluster_name, cluster_endpoint, node_group_name
```

## Verification Commands
```bash
cd terraform/envs/lab && terraform fmt -check && terraform validate && terraform plan
make up
aws eks update-kubeconfig --name eks-shopops --region us-east-1
kubectl get nodes
kubectl get pods -n kube-system | grep ebs-csi
make down
```
