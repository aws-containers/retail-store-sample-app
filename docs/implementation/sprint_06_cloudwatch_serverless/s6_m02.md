# S6-M02 - Python Lambda: write the incident to DynamoDB and a JSON report to S3

## Why this issue exists
A serverless function that reacts to the alarm and keeps a record of every incident (queryable in DynamoDB, archived as JSON in S3).

## Steps
1. lambda/handler.py (Python 3.12): parse the SNS event (`event['Records'][0]['Sns']['Message']` is a JSON string with AlarmName, NewStateValue, NewStateReason, StateChangeTime). Create an incident dict: id (uuid4), alarm name, state, reason, time, source.
2. Write the item to table shopops-incidents (boto3 resource Table.put_item) and the full JSON to s3://shopops-incidents-<account>/incidents/<date>/<id>.json (put_object). Table/bucket names from environment variables.
3. Terraform: aws_lambda_function with role = LabRole ARN, archive_file for the zip, environment variables, aws_lambda_permission for SNS, aws_sns_topic_subscription (protocol lambda).
4. Log with print/logging; make the function idempotent-friendly (new uuid per call is fine).
5. Document the record schema in lambda/README.md.
6. Test locally with a sample SNS event file (lambda/events/sample_sns.json) then in AWS with `aws lambda invoke`.

## Useful commands
```bash
aws lambda invoke --function-name shopops-incident-handler --payload fileb://lambda/events/sample_sns.json out.json
aws dynamodb scan --table-name shopops-incidents --max-items 3
aws s3 ls s3://shopops-incidents-<account>/incidents/ --recursive
```
