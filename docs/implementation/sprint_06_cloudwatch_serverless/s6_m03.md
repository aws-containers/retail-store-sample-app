## Why this issue exists
Prove the full chain works and explain, in writing, what each monitoring tool is good at.

## Steps
1. Chain test with set-alarm-state: confirm DynamoDB item + S3 object appear. Screenshot.
2. Optional real test: run a CPU stress pod in namespace retail (e.g., a busybox loop) and see whether the alarm reaches ALARM within about 10-15 minutes.
3. Write docs/observability_comparison.md (1 page): granularity, cost, what each sees (EC2 node metrics vs pod/Kubernetes metrics), alerting path, setup effort, when to use which. Include one screenshot from each.
4. Have another member review it.

## Useful commands
```bash
aws cloudwatch set-alarm-state --alarm-name shopops-node-cpu-high --state-value ALARM --state-reason 'e2e test'
```
