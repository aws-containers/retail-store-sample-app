# S5-M03 - PrometheusRule alert for CrashLoopBackOff and test it

**Sprint:** S5 Prometheus & Grafana (PDF Step 5 (3 h))  
**Owner:** C

**Depends on:** S5-M01, S3-M02  
**Teacher's requirement:** PDF Step 5 'test a PrometheusRule alert (CrashLoopBackOff)'; Deliverable 4 'tested alert rule'

## Why this issue exists
Shows the alerting chain works: a pod crashes, Prometheus detects it, the alert fires.

## Steps
1. Create helm-values or k8s manifest monitoring/prometheusrule-crashloop.yaml: kind PrometheusRule in namespace monitoring with label `release: monitoring` (must match the Helm release name or Prometheus ignores the rule), expr `kube_pod_container_status_waiting_reason{reason="CrashLoopBackOff"} == 1`, for: 1m, severity label, summary/description annotations.
2. Test: `kubectl run crash --image=busybox -n retail -- sh -c 'exit 1'` (restart policy default makes it crash loop), watch Prometheus UI -> Alerts: Pending then Firing. Screenshot.
3. Delete the test pod afterwards.

## Useful commands
```bash
kubectl apply -f monitoring/prometheusrule-crashloop.yaml
kubectl run crash --image=busybox -n retail -- sh -c 'exit 1'
kubectl delete pod crash -n retail
```
