# S5-M01 - Install kube-prometheus-stack with persistent gp3 volumes

**Sprint:** S5 Prometheus & Grafana (PDF Step 5 (3 h))  
**Owner:** C  
**Estimate:** 1.5 h  
**Depends on:** S2-M05, S3-M02  
**Teacher's requirement:** PDF Step 5 'kube-prometheus-stack via Helm in `monitoring` namespace with persistent EBS gp3 volumes'

## Why this issue exists
Prometheus (metrics), Alertmanager and Grafana in one Helm chart. Persistence means metrics and dashboards survive pod restarts.

## Steps
1. helm repo add prometheus-community https://prometheus-community.github.io/helm-charts && helm repo update.
2. Create helm-values/kube-prometheus-stack.yaml with: Prometheus storage via prometheus.prometheusSpec.storageSpec.volumeClaimTemplate (storageClassName gp3, accessModes ReadWriteOnce, 10Gi), Grafana persistence (grafana.persistence.enabled true, storageClassName gp3, size 5Gi), modest retention (for example 3d), and small resource requests.
3. Admin password for Grafana: set grafana.adminPassword from a --set at install time or read the generated secret; do not commit it.
4. `helm install monitoring prometheus-community/kube-prometheus-stack -n monitoring --create-namespace -f helm-values/kube-prometheus-stack.yaml`. Release name is `monitoring` (the PDF's cleanup script uninstalls `monitoring`).
5. Access with port-forward: `kubectl port-forward -n monitoring svc/monitoring-grafana 3000:80` and `svc/monitoring-kube-prometheus-prometheus 9090`.
6. Pin the chart version in the README so everyone installs the same one.

## Useful commands
```bash
kubectl get pods,pvc -n monitoring
kubectl top nodes
```

## Watch out
- RISK: memory on 2 small nodes - keep retention small and disable what you do not need. Check `kubectl top nodes` after install.
- PVC Pending -> go back to S2-M05 risk note.
- Service names depend on the release name; verify with `kubectl get svc -n monitoring`.
