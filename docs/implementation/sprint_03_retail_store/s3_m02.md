## Why this issue exists
First end-to-end proof: the retail store opens in a browser from the internet. The upstream README says `kubectl get svc ui` gives the frontend load balancer, so no ingress controller is needed.

## Steps
1. `kubectl apply -k k8s/` then `kubectl wait --for=condition=available deployments --all -n retail --timeout=300s`.
2. Get the URL: `kubectl get svc ui -n retail`. EXTERNAL-IP is a DNS name and may take 2-5 minutes. Open it in the browser, browse products.
3. If EXTERNAL-IP stays <pending>, check subnet tags (S2-M02) with `kubectl describe svc ui -n retail`.
4. Check node capacity: `kubectl top nodes` and `kubectl get pods -n retail -o wide`. Write the result in k8s/README.md (see warning).
5. Document the 'how to find the URL' one-liner in the README.

## Useful commands
```bash
kubectl apply -k k8s/
kubectl get pods -n retail
kubectl get svc ui -n retail -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'
```

- RISK: 2x t3.medium (about 4 GB each) must hold the Java services + in-cluster databases now, and Prometheus later (S5). If pods are Pending (Insufficient memory) report it here: options are lowering requests, or raising the node group max from 3 (it is allowed to grow).
- Everything is destroyed at the end of the session, so the LB DNS name changes each time.
