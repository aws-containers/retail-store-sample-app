# S3-M01 - Import the upstream manifests into k8s/ with kustomize (namespace retail)

**Sprint:** S3 Retail Store & DynamoDB (PDF Step 3 (2.5 h))  
**Owner:** B  
**Estimate:** 45 min  
**Depends on:** S2-M04  
**Teacher's requirement:** PDF section 3, Step 3 'unified Kubernetes manifest from the AWS repo' + namespace 'retail'

## Why this issue exists
The upstream repository publishes one all-in-one Kubernetes manifest per release (kubernetes.yaml). We pin it in Git, so the cluster content is reproducible, and use kustomize to put everything in namespace `retail` and to patch it later without editing the upstream file.

## Steps
1. Download the file from the repo's releases page (https://github.com/aws-containers/retail-store-sample-app/releases) and save it as k8s/base/upstream-kubernetes.yaml. Write the release tag in k8s/README.md.
2. Read the file and write in k8s/README.md the list of objects it creates: which deployments, which databases/caches run in-cluster, which Service is a LoadBalancer. Do not guess - read it.
3. Create k8s/namespace.yaml (retail) and k8s/kustomization.yaml with `namespace: retail` and `resources: [namespace.yaml, base/upstream-kubernetes.yaml]`.
4. Check with `kubectl kustomize k8s/ | less` that every namespaced object has namespace retail.

## Useful commands
```bash
curl -L -o k8s/base/upstream-kubernetes.yaml https://github.com/aws-containers/retail-store-sample-app/releases/latest/download/kubernetes.yaml
kubectl kustomize k8s/ | grep -c 'namespace: retail'
```

## Done when (acceptance checklist)
- [ ] Pinned manifest + release tag recorded.
- [ ] kustomize renders without error and puts objects in `retail`.
- [ ] k8s/README.md lists the content of the manifest.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- Upstream applies to the default namespace; the `namespace:` transformer in kustomize fixes that, but check cluster-scoped or hardcoded namespace references in the output.

## Out of scope (do not do here)
- Applying it to the cluster (S3-M02).

## Handoff
`kubectl apply -k k8s/` is the one command that deploys the app.
