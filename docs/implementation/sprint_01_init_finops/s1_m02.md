# S1-M02 - Billing alert and FinOps rules

**Sprint:** S1 Initialization & FinOps (PDF Step 1 (1 h))  
**Owner:** ALL  
**Estimate:** 30 min each  
**Depends on:** S1-M01  
**Teacher's requirement:** PDF section 3, Step 1, action 3 (first half); Deliverable 6 (Security & FinOps)

## Why this issue exists
Learner Lab gives a fixed budget. The EKS control plane ($0.10/h on a supported version), 2 EC2 nodes, load balancers and EBS volumes keep billing while the cluster exists. The PDF asks for a $10 billing alert and a destroy-at-end-of-session discipline.

## Steps
1. Try to create a $10 AWS Budget with an email alert (Billing console -> Budgets, or `aws budgets create-budget`).
2. If the service returns AccessDenied in Learner Lab, do NOT fight it: take a screenshot of the error, save it in docs/finops/, and note it in the README. Rely on the Learner Lab budget counter shown at the top of the lab page and tell the professor.
3. Write docs/finops.md: the session routine (start lab -> `make up` -> work -> `make down` -> CLI verification), a table of what costs money (EKS control plane, 2x t3.medium, Jenkins t3.small, load balancers, EBS volumes, ECR storage), and how to check the remaining budget.
4. Agree the rule: nobody leaves a session without running `make down` and the verification commands.

## Useful commands
```bash
aws budgets create-budget --account-id $(aws sts get-caller-identity --query Account --output text) --budget file://budget.json --notifications-with-subscribers file://notif.json
# (budget.json: 10 USD monthly cost budget; notif.json: ACTUAL >= 80% email) - if AccessDenied, document it
```
