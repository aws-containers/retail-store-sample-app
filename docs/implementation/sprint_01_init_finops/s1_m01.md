# S1-M01 - Set up tools and Learner Lab access (each member)

**Sprint:** S1 Initialization & FinOps (PDF Step 1 (1 h))  
**Owner:** ALL  
**Estimate:** 1 h each  
**Depends on:** nothing (can start now)  
**Teacher's requirement:** PDF section 3, Step 1, actions 1-2

## Why this issue exists
Before anything else, every member must be able to run AWS CLI, Terraform and kubectl against their own Learner Lab account. Learner Lab credentials are temporary and include a session token, so most 'it does not work on my machine' problems start here.

## Steps
1. Install: AWS CLI v2, Terraform (1.10 or newer), kubectl, Helm 3, Git, Docker, GitHub CLI (gh). Write the exact versions in docs/conventions.md.
2. Start your Learner Lab session. Open 'AWS Details' -> 'AWS CLI: Show' and copy the 3 values (access key id, secret, SESSION TOKEN) into ~/.aws/credentials under [default]. Set region = us-east-1 in ~/.aws/config.
3. Run the verification commands below. Comment the output of both on this issue.
4. Learn the rhythm: credentials expire when the session ends (about 4 h). You must re-copy them at every session start.

## Useful commands
```bash
aws sts get-caller-identity
aws iam get-role --role-name LabRole --query Role.Arn --output text
terraform version && kubectl version --client && helm version --short
```

## Done when (acceptance checklist)

- [ ] Tool versions added to docs/conventions.md via PR.
- [ ] I commented evidence (no secrets!) on this issue.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- Never paste the credentials in chat, Git or screenshots. If you do, end the lab session and restart it to get new keys.
- AccessDenied on iam:GetRole usually means the session token line is missing or expired.

## Out of scope (do not do here)
- Creating any AWS resource (next issues).
