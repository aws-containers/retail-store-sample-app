# S4-M04 - GitHub webhook trigger (and a script to refresh it each session)

**Sprint:** S4 Jenkins CI/CD Pipeline (PDF Step 4 (3.5 h))  
**Owner:** B  
**Estimate:** 1 h  
**Depends on:** S4-M03  
**Teacher's requirement:** PDF Step 4 'Configure the GitHub Webhook'; Deliverable 2 'Automated trigger via GitHub Webhook'

## Why this issue exists
The rubric wants an automatic trigger. Because Jenkins gets a new public IP at every `make up`, the webhook URL must be updated each session; we automate that so it takes seconds.

## Steps
1. Jenkins job: enable 'GitHub hook trigger for GITScm polling' (set in casc/job definition).
2. Create scripts/update_webhook.sh: uses `gh api` to create or update the repository webhook with payload URL http://<jenkins_ip>:8080/github-webhook/, content type json, event push. Run it at the end of `make up`.
3. Test: push a small change to main, watch the build start by itself; check 'Recent Deliveries' in the GitHub webhook page (green tick).

## Useful commands
```bash
gh api repos/<owner>/<repo>/hooks
bash scripts/update_webhook.sh
```

## Watch out
- Port 8080 must accept GitHub's webhook IP ranges (S4-M01), or deliveries show timeouts.
- Do not trigger builds from pushes that only change docs (optional path filter) to save budget.
