# S4-M02 - Jenkins reproducible setup (Configuration as Code + plugins)

**Sprint:** S4 Jenkins CI/CD Pipeline (PDF Step 4 (3.5 h))  
**Owner:** B  
**Estimate:** 1.5 h  
**Depends on:** S4-M01  
**Teacher's requirement:** PDF Step 4 'Configure the GitHub Webhook and Jenkinsfile'; Deliverable 7 reproducibility

## Why this issue exists
We run `make down` after every session, so Jenkins is destroyed too. Without automation, you would spend the first 30-40 minutes of every 4-hour session clicking through setup screens. This issue makes Jenkins configure itself at boot.

## Steps
1. Add the plugin list file jenkins/plugins.txt (git, workflow-aggregator, pipeline-stage-view, github, credentials-binding, configuration-as-code, job-dsl or a pipeline job definition, timestamps).
2. Add jenkins/casc.yaml: admin user (password from an environment variable, not in Git), skip setup wizard, one pipeline job `shopops-ui` that reads the Jenkinsfile from our GitHub repo (branch main).
3. GitHub access to a private repo: store a fine-grained personal access token ONCE per account in SSM Parameter Store as SecureString (`aws ssm put-parameter --name /shopops/github-token --type SecureString --value ...`, done by hand, never in Git). user-data reads it at boot using the instance role and registers it as a Jenkins credential.
4. Same for the Jenkins admin password: `/shopops/jenkins-admin`.
5. Test: `make down && make up` and confirm Jenkins comes back with the job already present.

## Useful commands
```bash
aws ssm get-parameter --name /shopops/github-token --with-decryption --query Parameter.Value --output text   # run on the Jenkins instance to test
```

## Done when (acceptance checklist)
- [ ] After a fresh `make up` the job exists with no manual UI step.
- [ ] No password/token in Git, Terraform state or user-data text.
- [ ] Documented in jenkins/README.md.
- [ ] PR reviewed by a different member and merged; commit messages start with the local ID
- [ ] Nothing secret committed (keys, tokens, kubeconfig, tfstate)

## Watch out
- RISK (unverified): reading a SecureString with LabRole should work (LabRole is broad). If it is denied, fall back to entering the token in the Jenkins UI each session and document the extra step.
- Fine-grained PAT needs read access to repository contents; commit status is optional.
